# V1 产品方案

## 1. 产品目标

把当前“脚本批量裁剪 + 人工删文件”的流程改造成一个可交互的桌面工具，使用户可以在一个界面内完成：

1. 拖拽导入多个比赛视频
2. 并行执行 AI 检测
3. 生成候选片段列表
4. 快速筛选无效片段
5. 预览候选片段
6. 手动微调起止时间
7. 最后只导出保留片段

## 2. 用户与场景

### 目标用户

- 需要批量整理竞技体操比赛视频的人
- 对运动员字幕有明确识别需求的人
- 愿意做人工复核，但不想再手动删大量冗余视频的人

### 典型场景

- 一次处理 3 到 20 个比赛视频
- 每个视频先由 AI 检测出运动员字幕候选
- 用户逐条审核候选片段
- 删除不需要的片段
- 对保留片段微调边界后统一导出

## 3. 要解决的核心问题

当前脚本版流程有三个主要问题：

1. 先批量裁剪再人工删除，浪费时间和磁盘空间
2. 缺少可视化审核界面，人工确认效率低
3. 无法在结果层直接微调边界，必须重新跑脚本或手工二次处理

V1 的核心价值不是“做一个视频编辑器”，而是“做一个高效率候选片段审核工具”。

## 4. V1 范围

### 必须做

- 拖拽导入多个视频
- 多视频任务队列
- 可配置并发检测数量
- 调用 AI 检测字幕
- 生成候选片段列表
- 候选片段列表筛选
- 片段预览
- 删除/保留候选片段
- 手动微调起止时间
- 最终导出保留片段
- 保存审核状态，防止中途中断后丢失

### 可以延后

- 自动生成高级时间轴缩略图缓存策略
- 帧级精确编辑
- 多轨编辑
- 批量重命名规则高级配置
- 团队协作或云同步
- 复杂统计报表

### 明确不做

- 通用视频剪辑器能力
- 转场、字幕、滤镜、配乐等非核心编辑功能
- 上传云端处理的视频工作流

## 5. 核心流程

### 5.1 导入阶段

用户拖拽多个视频文件进入应用。

系统执行：

- 校验文件格式
- 读取基础信息（文件名、时长、分辨率）
- 创建视频任务
- 将任务加入待处理队列

### 5.2 检测阶段

系统对视频执行检测流程：

1. 按固定时间间隔抽帧
2. 本地预筛字幕候选帧
3. 调用 AI 识别候选帧中的字幕信息
4. 合并同一运动员的重复检测
5. 生成候选片段列表

注意：

- AI 输出的是“某一帧里识别到的字幕信息”
- 时间戳由程序根据抽帧时间得到
- 候选片段由程序根据字幕时间关系推导得到

### 5.3 审核阶段

用户在界面中逐条审核候选片段：

- 查看运动员名、国家、时长、置信度
- 预览候选片段
- 删除无效片段
- 调整片段开始和结束时间
- 标记当前片段已审核

### 5.4 导出阶段

用户点击导出后，系统只对保留片段执行 ffmpeg 裁剪导出。

导出前提：

- 片段状态为保留
- 起止时间有效
- 输出目录可写

## 6. 候选片段是如何生成的

### 输入

AI 对候选帧输出类似结构：

```json
{
  "is_athlete_subtitle": true,
  "athlete_name": "OKAMURA Mana",
  "country": "JPN",
  "confidence": 0.92
}
```

程序同时知道该帧的抽样时间，例如 `214.0s`。

### 中间结果

多帧识别结果合并成一个字幕检测块：

```json
{
  "athlete_name": "OKAMURA Mana",
  "country": "JPN",
  "subtitle_start": 214.0,
  "subtitle_end": 220.0,
  "confidence": 0.92,
  "count": 4
}
```

### 候选片段生成规则

V1 使用业务近似规则：

- 当前字幕块开始时间作为候选开始参考
- 下一个字幕块开始时间作为候选结束参考
- 对开始时间增加默认前置留白

示例：

- A 字幕开始：214.0s
- B 字幕开始：386.0s

则候选片段可能为：

- `candidate_start = 212.0`
- `candidate_end = 386.0`

这不是最终结果，而是待人工审核的候选区间。

## 7. 数据模型

### 7.1 VideoTask

```json
{
  "id": "video_001",
  "file_path": "/path/to/video.mp4",
  "file_name": "2026 Baku World Cup. Women's FX + PH.mp4",
  "duration": 2985.2,
  "resolution": "1920x1080",
  "status": "queued"
}
```

### 7.2 DetectionBlock

```json
{
  "athlete_name": "OKAMURA Mana",
  "country": "JPN",
  "subtitle_start": 214.0,
  "subtitle_end": 220.0,
  "confidence": 0.92,
  "count": 4
}
```

### 7.3 CandidateClip

```json
{
  "id": "clip_001",
  "video_id": "video_001",
  "athlete_name": "OKAMURA Mana",
  "country": "JPN",
  "subtitle_start": 214.0,
  "subtitle_end": 220.0,
  "candidate_start": 212.0,
  "candidate_end": 386.0,
  "review_start": 212.0,
  "review_end": 386.0,
  "confidence": 0.92,
  "status": "pending"
}
```

`status` 取值建议：

- `pending`
- `kept`
- `deleted`
- `reviewed`
- `exported`

## 8. 页面级功能定义

### 首页 / 工作台

- 拖拽区域
- 视频任务列表
- 并发数设置
- 开始检测按钮
- 全局任务进度

### 审核页

- 候选片段列表
- 过滤条件区
- 视频预览区
- 时间轴和裁剪手柄
- 保留/删除/上一条/下一条操作

### 导出页或导出面板

- 导出目录选择
- 导出数量预览
- 导出进度
- 导出日志

## 9. 交互与体验原则

### 核心原则

- 减少切页
- 减少弹窗
- 尽可能键盘可操作
- 单条审核链路要短
- 让用户始终知道“当前处理到哪一步”

### 高优先级交互

- 点击列表即预览
- 预览自动从候选起点前若干秒开始
- 保留/删除后自动跳到下一条
- 起止时间修改后立即反映在预览区
- 支持快捷键审核

## 10. V1 验收标准

### 功能验收

- 能拖入多个视频并创建任务
- 能并发运行至少 2 到 4 个检测任务
- 能为每个视频生成候选片段列表
- 能对候选片段执行保留、删除和时间微调
- 能只导出保留片段
- 能在重启后恢复审核状态

### 体验验收

- 用户审核一条候选片段的平均操作链路不超过 5 次交互
- 切换候选片段到开始预览的等待时间应尽量控制在 1 秒内
- 主要操作支持快捷键

### 工程验收

- 原有脚本流程仍可独立运行
- 新架构不强耦合 shell 脚本
- 检测、审核、导出状态均可结构化保存

## 11. 风险与边界

### 风险

- AI 识别质量仍然会决定候选片质量上限
- 并发过高会碰到 API 限流
- 精确裁剪通常不能一直依赖 `-c copy`
- 时间轴缩略图生成会增加额外处理时间

### 边界

- V1 解决的是“高效审核候选片段”
- V1 不追求替代 Final Cut 或 Premiere
- V1 的重点是流程效率，而不是复杂编辑能力

## 12. 建议开发顺序

1. 重构 Python 引擎层
2. 定义项目状态与候选片 JSON 结构
3. 搭建桌面壳与 React 前端
4. 打通导入与检测任务流
5. 实现审核页与预览
6. 实现微调与导出
7. 再优化时间轴与交互细节
