# 交互稿结构

## 1. 交互目标

界面的核心目标不是“复杂编辑”，而是让用户用最少动作完成：

1. 找到正确片段
2. 删除错误片段
3. 微调边界
4. 快速进入下一条

因此交互设计必须围绕：

- 高信息密度
- 低操作成本
- 快速切换
- 清晰状态反馈

## 2. 信息架构

V1 建议采用单窗口三层结构：

1. 顶部全局工具栏
2. 中部主工作区
3. 底部状态区

## 3. 页面结构

### 3.1 顶部工具栏

包含：

- 应用标题
- 导入按钮
- 当前项目名称
- 并发数设置
- 开始检测按钮
- 导出按钮
- 设置入口

目标：

- 所有全局动作固定在顶部
- 不让用户在多个页面里找入口

### 3.1.1 导入交互原则

导入必须同时支持两种方式：

- 主方式：直接把视频文件拖到应用窗口中
- 备选方式：点击导入按钮，再通过系统文件选择器选择文件

其中主方式必须是第一优先级体验，而不是附属能力。

具体要求：

- 用户把视频拖到应用窗口时，窗口整体进入可投放状态
- 松手后弹出一个轻量确认层，展示待导入文件数量和文件名摘要
- 用户确认后立即导入
- 不要求用户再点一次“选择文件”

这意味着导入交互不应只设计成传统上传按钮 + 文件弹窗流程。

### 3.1.2 窗口级拖拽行为

当用户把文件拖到应用窗口时：

- 整个主窗口出现高亮边框或遮罩
- 中间显示明确文案，例如“松手即可导入视频”
- 非视频文件要给出不可投放提示

当用户松手后：

- 打开导入确认层
- 显示将导入的文件数量
- 显示文件名列表或摘要
- 提供“确认导入”和“取消”两个动作

确认后：

- 立即创建视频任务
- 将任务加入队列
- 返回主界面

### 3.1.3 传统导入方式

传统导入方式保留，但作为备选：

- 顶部保留“导入”按钮
- 点击后打开系统文件选择器
- 选中文件后进入同一个导入确认层

无论拖拽导入还是手动选择，都应进入同一套确认和入队流程，避免两套逻辑分叉。

### 3.2 中部主工作区

中部采用三栏布局。

#### 左栏：视频任务区

显示：

- 视频文件名
- 时长
- 状态
- 候选片段数
- 已审核数

支持：

- 选择当前视频
- 查看检测进度
- 查看失败原因
- 重新检测单个视频

#### 中栏：候选片段区

显示每个候选片段的卡片或紧凑列表项：

- 缩略图
- 运动员名
- 国家
- 起止时间
- 时长
- 置信度
- 审核状态

支持：

- 单击选中
- 多条件筛选
- 按状态过滤
- 按置信度排序
- 按时长排序

#### 右栏：预览与裁剪区

这是 V1 的核心区域。

包含：

- 视频播放器
- 当前片段标题信息
- 当前片段时间范围
- 裁剪时间轴
- 保留 / 删除 / 上一条 / 下一条按钮

## 4. 审核主链路

理想审核链路：

1. 用户点击候选片段
2. 右侧自动预览
3. 用户判断是否有效
4. 无效则删除
5. 有效则必要时微调边界
6. 保留并进入下一条

设计要求：

- 单条审核不应强迫用户离开当前上下文
- 删除或保留后自动跳转到下一条待审核项
- 当前视频审核完后自动切到下一个视频

## 5. 片段列表交互

### 列表项内容

每条候选片段建议显示：

- 主标题：运动员名
- 副标题：国家 + 视频内时间
- 辅助信息：时长 + 置信度
- 状态标识：待审核 / 保留 / 删除 / 已导出

### 列表项操作

- 单击：加载到右侧预览
- 双击：直接开始播放
- 右键或更多菜单：
  - 保留
  - 删除
  - 重置边界
  - 定位到原视频时间

### 筛选区

建议固定在候选片段区顶部：

- 状态筛选
- 姓名搜索
- 国家筛选
- 时长范围
- 低置信度优先

默认筛选建议：

- 只显示 `pending`

这样用户打开后就直接处理待审核项，不会被已处理数据干扰。

## 6. 预览区交互

### 播放器行为

- 选中候选片段后自动加载对应原视频位置
- 默认从 `review_start - 2s` 开始预览
- 播放结束时停在 `review_end`
- 支持空格播放/暂停

### 预览信息

播放器上方或下方显示：

- 当前运动员名
- 国家
- 候选片段序号
- 当前时间 / 当前片段范围

## 7. 时间轴与裁剪交互

### V1 时间轴目标

不追求完整剪辑软件级别复杂度，但必须做到：

- 直观看到候选片段边界
- 支持拖动左右手柄
- 支持点击跳转
- 支持播放头定位
- 调整后可立即预览

### 时间轴组成

- 缩略图带
- 当前播放头
- 左边界手柄
- 右边界手柄
- 已选区高亮

### 交互规则

- 拖左手柄：修改 `review_start`
- 拖右手柄：修改 `review_end`
- 拖动播放头：改变当前预览位置
- 双击时间轴：以该点为中心重新定位预览

### 边界约束

- `review_start < review_end`
- 保证最小时长阈值，例如 1 秒
- 边界不能超出视频时长

### 微调方式

除了鼠标拖拽，还要支持按钮或快捷键：

- 左边界 -0.2s
- 左边界 +0.2s
- 右边界 -0.2s
- 右边界 +0.2s

这是保证“简洁易用”的关键，因为纯拖拽不够精确。

## 8. 快捷键方案

建议 V1 就支持：

- `Space`: 播放 / 暂停
- `Enter`: 保留并跳下一条
- `Delete`: 删除并跳下一条
- `Left`: 后退短时间
- `Right`: 前进短时间
- `A`: 左边界左移
- `D`: 左边界右移
- `J`: 右边界左移
- `L`: 右边界右移

目标：

- 鼠标负责定位
- 键盘负责高频审核

## 9. 状态设计

### 视频级状态

- `queued`
- `detecting`
- `ready_for_review`
- `reviewing`
- `done`
- `error`

### 片段级状态

- `pending`
- `kept`
- `deleted`
- `reviewed`
- `exported`

状态显示必须统一且明显，避免用户不知道哪些已经处理。

## 10. 异常与边界交互

### 检测失败

要显示：

- 失败原因
- 重试按钮
- 不影响其他视频继续处理

### 没有候选片段

要显示明确空状态：

- 未检测到有效字幕
- 可重跑检测
- 可调整检测参数后重试

### 导出失败

要显示：

- 哪些片段失败
- 错误原因
- 是否允许单条重试

## 11. 视觉与布局建议

### 风格方向

- 专注、轻量、偏工具型
- 以内容和效率为中心，不做重装饰
- 视频区保持大而稳定

### 布局优先级

- 右侧预览区优先最大化
- 中栏列表次之
- 左栏任务列表可以更窄

### 颜色建议

- 默认中性色
- `kept` 用清晰但不过度抢眼的绿色系
- `deleted` 用克制的红色系
- `pending` 用高可见但不焦躁的强调色

## 12. 交互稿输出建议

给 Google AI Studio 或设计稿工具时，建议先拆成 4 张核心稿：

1. 窗口级拖拽导入态
2. 检测完成后的审核主界面
3. 片段微调状态
4. 导出状态面板

每张稿都要明确：

- 主信息区域
- 主操作按钮
- 当前焦点
- 成功态 / 空态 / 错误态

其中第 1 张稿必须体现：

- 用户把视频拖到整个应用窗口
- 应用进入可投放状态
- 松手后出现导入确认层
- 顶部同时保留传统“导入”按钮

## 13. 交互验收标准

- 新用户第一次打开后，不看文档也能完成“导入 -> 检测 -> 审核 -> 导出”
- 高频审核操作可以主要通过键盘完成
- 从点击候选项到开始预览的路径足够短
- 用户不会误以为“删除片段”是删除原视频
- 用户始终能清楚区分“候选时间”和“最终导出时间”
