# Google AI Studio 前端设计输入稿

以下内容可直接作为 Google AI Studio 的前端设计输入。

---

请为一个“体操比赛视频候选片段审核工具”设计桌面应用前端界面。

## 一、产品定位

这不是通用视频剪辑软件，也不是复杂的非线性编辑器。

这是一个高效率的“候选片段审核工具”，用于处理竞技体操比赛视频。

核心流程是：

1. 用户把多个比赛视频拖入应用
2. 系统调用 AI 检测视频中的运动员字幕，生成候选片段列表
3. 用户在界面中快速筛选、预览、删除无效片段
4. 用户可以手动微调片段起止时间
5. 最后只导出保留的片段

设计重点不是复杂编辑，而是：

- 快速导入
- 快速审核
- 快速保留 / 删除
- 快速微调边界
- 清晰的任务状态

## 二、目标用户

目标用户是需要批量整理竞技体操比赛视频的人。

他们通常会：

- 一次处理多个比赛视频
- 根据运动员字幕识别候选片段
- 对候选结果进行人工复核
- 删除无效片段
- 调整有效片段边界后导出

他们重视的是效率、清晰度和低认知负担。

## 三、核心交互要求

### 1. 导入方式

导入必须同时支持两种方式：

- 主方式：用户把视频直接拖到整个应用窗口里
- 备选方式：顶部点击“导入”，再通过系统文件选择器选择文件

注意：

- 主方式必须是第一优先级体验
- 不要把界面设计成传统网页上传框
- 整个应用窗口都应该支持拖拽导入

当用户拖动视频进入窗口时：

- 整个窗口出现明确的可投放高亮态
- 中央出现大号提示文案，例如“松手即可导入视频”
- 支持多文件拖入

当用户松手后：

- 弹出一个轻量确认层
- 展示待导入文件数量和文件名摘要
- 用户点击确认后立即导入

### 2. 审核主界面

审核必须尽量在单屏内完成，不要频繁跳转页面。

推荐三栏布局：

- 左栏：视频任务列表
- 中栏：候选片段列表
- 右栏：视频预览和裁剪区

### 3. 候选片段审核

用户审核一条候选片段时，应该可以快速完成：

1. 查看片段信息
2. 预览片段
3. 判断是否保留
4. 如果需要，微调起止时间
5. 进入下一条

界面要非常适合高频重复操作。

### 4. 微调交互

用户可以像 mac 预览里的裁剪体验那样，对时间区间进行快速微调。

要求：

- 有可视化时间轴
- 有左右裁剪手柄
- 有当前播放头
- 可点击跳转
- 可拖动边界
- 调整后可以立即预览

但不要设计成复杂专业剪辑软件。

## 四、页面结构要求

### 页面 A：窗口级拖拽导入态

需要设计一个“整个窗口进入拖拽导入状态”的界面。

必须包含：

- 桌面应用主窗口
- 整体高亮的拖拽接收态
- 大号中央提示文案
- 顶部仍然保留“导入”按钮
- 清晰告诉用户可以直接拖视频进来

这个页面要体现“这是桌面软件，不是网页上传表单”。

### 页面 B：审核主界面

这是最重要的页面。

布局建议：

- 左栏：视频任务列表
- 中栏：候选片段列表和筛选区
- 右栏：大尺寸视频预览 + 时间轴 + 操作按钮

左栏任务区需要展示：

- 视频文件名
- 时长
- 当前状态
- 候选数量
- 已审核数量

中栏候选片段区需要展示：

- 缩略图
- 运动员姓名
- 国家
- 起止时间
- 时长
- 置信度
- 状态标签

中栏上方需要有筛选与搜索：

- 按状态筛选
- 按运动员姓名搜索
- 按国家筛选
- 按时长筛选
- 按置信度排序

右栏预览区需要展示：

- 当前片段视频预览
- 当前运动员姓名和国家
- 当前片段序号
- 当前时间
- 可交互时间轴
- 保留 / 删除 / 上一条 / 下一条按钮

### 页面 C：片段微调状态

这是审核主界面的一个更聚焦状态。

重点展示：

- 更大的时间轴
- 左右边界手柄
- 当前选区高亮
- 缩略图带
- 精细调整按钮

这里要体现“简洁好用”，不是“功能很多”。

### 页面 D：导出状态面板

需要一个导出状态界面或面板，展示：

- 将导出的片段数量
- 导出目录
- 导出进度
- 成功 / 失败状态
- 日志或错误提示

## 五、视觉方向

请设计成一个专业、克制、偏工具型的桌面应用。

视觉要求：

- 简洁、现代
- 高信息密度但不拥挤
- 强调视频内容和效率
- 不要像普通后台管理系统
- 不要像网页 SaaS 上传平台
- 不要过度花哨

建议方向：

- 中性色为主
- 清晰层级
- 大面积稳定的视频预览区
- 状态颜色明确但克制

状态色建议：

- `pending`：清晰但不过度刺眼
- `kept`：克制的绿色
- `deleted`：克制的红色
- `error`：明确但不刺耳的警示色

## 六、交互细节要求

请重点考虑这些高频交互：

- 点击候选片段后立即在右侧预览
- 保留或删除后自动跳到下一条
- 支持键盘高频操作的视觉暗示
- 时间轴修改后立即反馈
- 用户始终知道当前处理到了哪个视频、哪条片段

请让界面明显区分这些概念：

- 原视频
- 候选片段
- 人工调整后的最终导出区间

不要让用户误以为“删除候选片段”就是删除原视频文件。

## 七、设计输出要求

请输出一套桌面应用界面方案，至少包含以下 4 个核心画面：

1. 窗口级拖拽导入态
2. 审核主界面
3. 片段微调状态
4. 导出状态面板

每个画面请尽量体现：

- 布局结构
- 信息层级
- 主要按钮
- 状态标签
- 关键交互元素

如果可以，请同时补充：

- 颜色方案
- 字体建议
- 间距和层级建议
- 组件风格建议

## 八、技术实现背景

这个前端后续计划使用 React 架构实现，并运行在桌面应用中。

因此设计时请尽量考虑：

- 适合 React 组件化拆分
- 适合桌面端交互
- 适配较宽屏幕
- 支持未来接入本地视频预览与时间轴交互

请输出结果时优先给出：

- 高保真桌面应用界面方案
- 清晰的布局结构
- 便于开发落地的组件划分
